한눈에 결론

제조 PoC 판정: NOT_READY

Haps™는 공식 문서 Copilot의 실행 기반을 갖췄지만, 실시간 제조 데이터부터 승인된 업무 조치까지 연결하는 코어는 아직 부족하다.

Executive Summary확인된 판단
A. Current State식품 규제 Copilot. 제조 Intelligence/Control의 종단 서비스는 미완성.
B. Most Complete ComponentsLogosAX 수집·검색·인용, 서버 실행 이력, 문서 승인 스냅샷, Aegis 로컬 HMAC.
C. Critical Missing Components제조 Context, Private ACL, 산업용 Connector, Event/Time-series, 서버 Action Gateway.
D. Architecture Risks프로세스·저장소·CLI 결합, 비영속 큐, 모델 직렬 호출 지연, UI/실행 상태 불일치.
E. Security Risks소스 결함 5건: 중간 2건·낮음 3건. 경로별 전송 정책·자원 제한·인증 및 감사 귀속 보강 필요.
F. On-Prem ReadinessNOT_READY: 일부 구성요소만 로컬이며 전체 서비스 오프라인 실행은 미연결.
G. Vietnam PoC ReadinessNOT_READY: 요청된 Line 7 분석→Supervisor 승인→MES/정비 Action 종단 경로 부재.
H. Next Action보안 → Private RAG/SOP → 제조 Context → Edge/Event → 서버 승인·업무 Connector.

핵심 판단과 영향

  • 검색·인용 코드는 실재한다 → 문서 Copilot 기반은 재사용할 가치가 있다 → 전체를 다시 만드는 접근은 불필요하다.
  • 현장 Context·Connector가 없다 → 실시간 제조 판단 입력을 구성하지 못한다 → 프롬프트 개선만으로 제조 PoC를 완성할 수 없다.
  • Themis·Aegis는 제한 범위에서 실행된다 → 완전 미구현도, 제조 서비스 완성도 아니다 → 각각 현장 데이터·권한·신뢰 경계를 연결해야 한다.
  • 전체 로컬 경로가 없다 → 외부 전송 금지 고객 요구와 충돌할 수 있다 → 고객의 데이터 반출 조건을 개발 착수 전에 확정해야 한다.

결정 필요: 첫 PoC를 읽기 전용 현장 분석으로 할지, Supervisor 승인 후 정비 업무까지 포함할지 선택해야 한다. PLC 제어는 첫 PoC에서 제외할 것을 권고한다.

즉시 영향: 요청된 전체 제조 시나리오를 지금 준비 완료로 제시할 수 없다. 일정·예산은 미산정이며, 요금 업그레이드를 기능 구현의 대안으로 볼 수 없다.

다음 검토: AlexLAB 프로젝트 책임자가 PoC 범위·외부 전송 조건을 확정하고, 개발 담당자가 현장 장치/API 계약과 P0 완료 기준을 정리하는 순서다. 이는 권고이며 담당 배정·개발 승인 완료를 의미하지 않는다.

감사 범위와 판정 기준

기준일은 2026-09-15다. 실제 저장소의 현재 작업 트리, 함수 호출 경로, DB Schema·마이그레이션, API, 설정과 테스트 소스, 제한된 로컬 기록을 대조했다. 설계·UI·interface·mock을 완료 증거로 인정하지 않았다.

판정의미
IMPLEMENTED실행 코드와 연결 경로가 존재한다. Production-ready를 자동 의미하지 않는다.
PARTIAL핵심 일부는 있지만 요구한 종단 기능이 미완성이다.
MOCK / UI_ONLY합성 결과 또는 클라이언트 표시·계약만 확인했다.
NOT_IMPLEMENTED조사 범위에서 구현체가 없거나 코드가 명시적으로 미구현이다.
UNKNOWN원격 적용·실환경 등 현재 증거로 판단할 수 없다.
READY / NOT_READY요청된 PoC 시나리오의 통과 여부다. 좁은 기능의 존재와 구분한다.

원격 DB의 실제 마이그레이션 적용, 배포 버전, 실장치·실모델 호출, 부하·침투 시험은 수행하지 않았다. 보안 검토 범위는 PARTIAL이다. 문서에 적힌 과거 PASS를 이번 회귀 시험 결과로 재사용하지 않았다.

이번 보고서는 감사 결과를 공개용으로 재구성한 파생본이다. 내부 상세본의 코드 위치·취약점 재현 정보·운영 식별자·로컬 경로는 게시하지 않는다. 애플리케이션 코드·DB·API·운영 배포 변경은 수행하지 않았다.

Haps·Tool·HITL의 실제 범위

실행 흐름은 인증/요청 → 제한된 대화 맥락 → 공식 근거 검색 → 위험 검토 → 인용 무결성 → 모델 합성 → 사용 인용 확인 → 로컬 봉인·이력이다. 순차 coordinator이며 자율적인 범용 Agent loop와는 다르다.

  • Model Router·Prompt 버전·timeout·오류 분류는 존재한다. 중앙 Prompt rollout과 공통 분산 Retry/실행 예산은 미완성이다.
  • 대화 Context는 최근 최대 6턴·5,400자다. 서버 이력 저장은 실구현이지만, 모델 맥락은 제한된 클라이언트 전달 이력을 사용한다. 장기 제조 Memory는 아니다.
  • Tool 정의·Scope·Approval 계약과 Mock adapter는 있지만 범용 Backend Tool Registry/Executor는 없다.
  • 문서의 승인·수정·반려·스냅샷·승인 후 출력 게이트는 실구현이다. 이를 제조설비 Action 승인으로 확대할 수 없다.
  • 검토 요청은 내부에 저장된다. 외부 전문가 실제 접수·담당 배정·재배정·기한 관리와 전달 확인은 연결되지 않았다.
  • 일반 업무 API의 관리자 권한 검사와 사용자별 신규 대화 이력 제한은 존재한다. 공장·교대·설비·도구별 세분 권한과는 다르다.

제조 Control Level: L1 Recommend. 문서 업무 일부의 L2 기능은 있으나, 제조 업무 L2 종단 연결이나 L3 Human-approved Machine Control, L4 Autonomous Control 구현 증거는 없다.

LogosAX 수집·Chunking·RAG

실제 수집 파이프라인

Fetch / Upload→Parse / 선택 OCR→정규화 / Chunk→Embedding / Index→검색 / 근거 / 인용
  • PDF·DOCX·HWPX·텍스트의 로컬 파싱과 선택 OCR, 페이지 checkpoint·timeout·실패 상태가 존재한다.
  • 문서 이미지 영역 선별과 지연 렌더링은 있지만, 범용 의미 기반 이미지 분류라고 볼 수는 없다.
  • Google Drive 수집은 검토 대기 초안을 만든다. 별도 직접 업로드의 품질 게이트 기반 게시 경로와 승인 정책이 같지 않다.
  • Worker는 thread/process·로컬 상태·체크포인트 중심이다. 일부 재시도 안전성은 있으나 분산 durable queue는 없다.

검색과 답변 생성

  • 로컬 BGE-M3 1,024차원 임베딩을 사용한다. 설계 이미지의 1,536차원 표기와 다르다.
  • Dense 60% / Sparse 40%의 가중 RRF가 있다. 로컬 Sparse는 BM25이며 원격 FTS를 같은 구현으로 볼 수 없다.
  • 로컬 Vector 저장은 SQLite와 cosine 행렬 검색이다. ANN 인덱스로 평가하지 않았다. 원격 pgvector 경로는 선택적으로 존재한다.
  • LLM이 관련성을 재평가하고, 근거가 부족한 경우 제한된 추가 질의와 두 번째 검토를 수행한다. 점수는 교정된 확률적 Confidence가 아니다.
  • 공식 출처 역할·품질·hash·revision 필터와 검색 후보/제외 이유·인용 사용 trace가 존재한다.
  • 선정 근거와 본문에서 실제 사용한 인용은 구분된다. Hash 검증 통과를 의미적 사실 검증이나 법률 최신성 보증으로 볼 수 없다.
  • 기존 일부 문서별 경로에는 식품 주제 규칙이 남아 있다. 전체 하드코딩이 제거되었다는 평가는 하지 않았다.

지연 판단: 직렬 모델 호출과 재순위화 비용이 구조적 부담이다. 검색·생성·큐 구간별 실측이 필요하며 고정 정답이나 특정 PDF 강제 채택을 속도 개선으로 인정하지 않는다. 1.5초 응답 또는 서비스 SLA는 이번 감사로 보장할 수 없다.

Enterprise Private RAG와 SOP 수명주기

현재 공식 공개 근거 검색은 동작 코드가 있지만, 회사 Private 검색은 운영 세션 연결이 부족하여 검색 전 차단된다. 이것은 안전한 실패 처리이지 권한 기반 Private RAG 완성의 증거는 아니다.

- ThemisAX는 수동 입력에 대한 결정론적 평가 코드가 있다. 단순 LLM 프롬프트만은 아니다.
- Themis 채팅 위험 검토는 안내용이며 실제 센서 기반 현장 판정과 다르다.
- AegisAX는 로컬 해시/HMAC·순서 검증·버퍼/ack 코드가 있다.
- Aegis 로컬 버퍼를 실제 장치 펌웨어·원격 동기화 완료로 인정하지 않는다.
- AI Brain은 실제 문서·질의 기록을 시각화한다. 전부 가상은 아니지만 운영 제조 지식 그래프는 아니다.
- 문서 승인·검토·스냅샷은 존재한다. 전문가 외부 이관과 제조 Action 승인은 미완성이다.

3. 제조 확장 핵심 Gap
- Tenant/Plant/Department/User/Document/Section ACL의 검색 전 종단 강제 미완성.
- 승인·시행·만료·폐기 SOP의 답변 근거 사용 정책 미완성.
- Plant→Line→Machine→Sensor 및 Incident/SOP/Rule을 묶는 Context Engine 부재.
- 실제 MQTT/Modbus/OPC-UA 산업용 Connector와 MES/SCADA 업무 연결 부재.
- 제조 Event Bus, 시계열 수집·집계, Incident 상관분석 부재.
- 예지보전·예측·결함 예측 ML은 구현 증거 없음.
- 서버 Policy/Approval/Safety/Connector로 이어지는 Safe Action Gateway 부재.
- 제조 제어 수준은 L1 Recommend. 문서 업무 일부 L2를 제조제어 L2/L3로 확대하지 않는다.

4. 기술적 판단
HaccpOS를 Food Manufacturing Vertical로 유지하면서,
Haps Manufacturing Intelligence Core를 분리하는 방향은 기술적으로 가능하다.
먼저 공통 Context·권한·Event·Connector 인터페이스를 만들고 검증해야 한다.
즉시 마이크로서비스로 나누거나 Graph DB를 도입하는 것 자체가 해법은 아니다.
Supabase/AI 요금 상향만으로 미구현 코어가 해결되지는 않는다.
브랜드 변경, 개발 착수, 일정·예산 승인은 이번 감사에 포함되지 않는다.

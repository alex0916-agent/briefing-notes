4. Scenario B — 실제 MQTT 제조데이터 데모

베트남 고객에게 가장 강력한 다음 단계 데모. 올젠케어 전력·온도·압력·카운트 장비 중 1종을 선정한다.

[실제 센서]
   ↓ MQTT
[AllgenCare Gateway]
   ↓
[Haps Edge Adapter]
   ↓ Canonical Telemetry
[Time-Series / Event]
   ↓
[Haps Dashboard]

권장 시연

  1. 센서 실시간 값 표시
  2. Device ID / Plant / Line / Asset 매핑 표시
  3. 정상 범위에서 값 변화 확인
  4. Threshold를 넘는 테스트 데이터 발생
  5. Event/Alert 생성
  6. Haps가 “어느 설비에서 어떤 이상이 발생했는지” 설명

첫 장치 추천

온도 또는 전력계. 변화가 눈에 잘 보이고 고객이 이해하기 쉬우며 안전하게 Read-only로 시연할 수 있다.

5. Scenario C — Manufacturing Intelligence Golden Demo

이 시나리오를 베트남 제조 PoC의 최종 데모 목표로 둔다.

사용자: "Line 1의 현재 상태를 분석해줘"

1. 실시간 Sensor / 운영 데이터 조회
2. Plant / Line / Machine / Sensor Context 식별
3. 이상 Event 확인
4. 승인·시행 중인 SOP 검색
5. 과거 유사 Incident 검색
6. ThemisAX Risk / Severity 판단
7. Haps 원인 후보 + 근거 + 조치 권고
8. Supervisor 승인
9. Incident 생성
10. MES/CMMS 업무 Action 요청

첫 PoC는 10단계에서 PLC Write를 제외한다. 업무 Action은 Incident/정비요청/알림 수준으로 제한한다.

11. 고객 질문 대응 메시지

질문권장 답변 방향
사내 문서가 외부로 나갑니까?Private RAG와 Hybrid/On-Prem 구조를 제공하도록 설계 중이며, PoC에서 데이터 경계를 먼저 확정한다.
MES 연결됩니까?Connector 방식으로 연동한다. 현재 고객 MES API/프로토콜 확인 후 PoC Connector 범위를 확정한다.
AI가 PLC를 직접 제어합니까?첫 단계는 하지 않는다. 현재 전략은 Recommend → Supervisor Approval → Workflow Action이며, 장비제어는 안전 검증 후 별도 단계다.
현지 A/S 됩니까?AlexLAB 플랫폼 + 올젠케어 Hardware/Edge + 베트남 Local Field Partner 구조를 준비한다.

12. PoC 제안으로 연결하는 종료 멘트

“오늘 보여드린 기능을 귀사 생산라인 전체에 바로 적용하자는 제안은 아닙니다.
우선 한 공장, 한 라인, 한 장치를 기준으로 실제 데이터를 연결하고,
귀사 승인 SOP와 함께 Haps가 이상상황을 이해하고 조치를 권고하는지를 검증하겠습니다.
그 결과를 기준으로 MES·SCADA·On-Prem 범위를 단계적으로 확장하겠습니다.”

13. 권장 첫 PoC 범위

  • 공장 1곳
  • 라인 1개
  • 실장치 1종
  • Read-only MQTT
  • SOP 3~5개
  • Threshold Event 1종
  • Themis Risk Rule 1~3개
  • Supervisor Approval
  • Incident 생성
  • PLC Write 제외

성공 기준: 실제 Sensor → Context → SOP → Decision → Approval → Incident 흐름이 하나의 Trace ID로 재현 가능할 것.

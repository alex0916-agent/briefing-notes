ALEX LAB COLLABORATION STANDARD

브리핑·보고서 GitHub Pages 협업 문서 운영 표준

앞으로 AlexLAB 관련 브리핑, 기술보고서, 감사결과, 전략자료, 회의자료 및 협업문서는 GitHub Pages에 게시하고 링크로 확인·공유하는 것을 기본 전달 방식으로 정의합니다.

GitHub PagesBriefingReportTechnical AuditCollaboration

1. 기본 운영 원칙

  1. 완성된 브리핑·보고서는 채팅 본문에만 남기지 않고 GitHub Pages용 HTML 문서로 생성합니다.
  2. 기본 저장소는 alex0916-agent/briefing-notes를 사용합니다.
  3. 문서는 기본적으로 briefs/ 경로 아래에 저장합니다.
  4. 게시 후 사용자가 바로 열어볼 수 있는 GitHub Pages 링크를 전달합니다.
  5. 기존 문서는 원칙적으로 삭제하거나 덮어쓰지 않고 날짜·주제별 이력으로 남깁니다.
  6. 정정본 또는 개정본이 필요한 경우 Version 또는 Revised 표기를 사용합니다.

3. 파일명 표준

YYYY-MM-DD-topic-name.html

예시:

2026-09-15-haps-edge-mqtt-standard.html
2026-09-15-haps-technical-audit.html
2026-09-16-allgencare-vietnam-strategy-meeting.html

파일명은 영문 소문자와 하이픈을 기본으로 사용하고, 같은 주제의 개정본은 -v2, -revised 등으로 구분합니다.

6. 링크 전달 표준

작업 완료 보고에는 아래 정보를 포함합니다.

  • 취한 조치: 어떤 문서를 생성·업데이트했는지
  • 결과: 게시 경로 및 상태
  • 확인 링크: GitHub Pages URL
  • 필요 시: 다음 검토 또는 의사결정 포인트

7. 보안·공개 원칙

briefing-notes 저장소가 Public인 경우 공개 가능한 정보만 게시합니다.

  • API Key, Password, Token, 인증서 Private Key 금지
  • 고객사의 비공개 서버 주소·내부 IP·계정정보 금지
  • 취약점 재현에 필요한 민감한 상세정보 금지
  • 계약·개인정보·영업비밀은 공개 여부를 별도 판단
  • 내부 전용 자료는 Public GitHub Pages 대신 별도 Private 저장 방식 사용

8. 문서 상태 표준

DRAFT
REVIEW
APPROVED
PUBLISHED
REVISED
ARCHIVED

대외 또는 파트너 공유 자료는 가능한 경우 문서에 현재 상태를 명시합니다.

9. 변경 관리

  • 사실관계·숫자·아키텍처가 변경되면 개정 이력을 남깁니다.
  • 기존 링크 보존이 중요한 경우 기존 문서를 업데이트하고 Revision을 명시합니다.
  • 중대한 방향 변경은 새 파일로 분리하고 이전 문서와 관계를 표시합니다.
  • 임의로 과거 보고서를 삭제하지 않습니다.

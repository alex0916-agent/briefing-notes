한눈에 결론

구현 준비: CONDITIONAL_READY · 실제 베트남어 제조 데모: NOT_READY

Haps™에는 다국어 검색과 원문 인용에 재사용할 기반이 있습니다. 그러나 언어 설정부터 사내 SOP 검색·현장 판정·응답까지 이어지는 다국어 운영 경로는 아직 완성되지 않았습니다.

  • UI 번역만의 문제가 아닙니다. 사용자 언어 계약, 대화 맥락, 검색 토큰화, 번역 승인과 실제 제조 Context를 함께 연결해야 합니다.
  • 기존 코어는 재사용합니다. BGE-M3 dense 검색 코드, 원문 hash·인용, 구조화 Themis 평가, 대화 저장과 보고서 변수 모델이 기반입니다.
  • 언어 편향을 실제로 재현했습니다. 영어·베트남어 후속 질문의 검색 맥락 누락과 베트남어 성조가 있는 단어의 분절 문제가 확인됐습니다.
  • 같은 사실은 같은 판정이어야 합니다. 원문·Context·Rule·Decision은 하나로 유지하고 대화·UI·알림·보고서의 표현만 바꿉니다.

결정 필요: P0 활성 화면 범위, 베트남어 제조 용어 검수자, 고객 문서 외부 전송 조건, 평가용 문서·질문 세트를 확정해야 합니다.

영향: 모델의 다국어 능력만으로 실제 제조 데모 준비 완료를 주장할 수 없습니다. 일정·예산·응답속도는 아직 확정하지 않았습니다.

다음 행동: 공통 계약·합성 검수 세트를 먼저 확정하고, 사용자 Locale → UI → Chat 응답까지 한 흐름으로 연결하는 P0 작업부터 진행하는 것을 권고합니다.

이번 결과는 감사·설계·구현 계획입니다. 기능 구현, DB 변경, 새 AI Provider 도입 또는 제품 배포를 수행한 보고서가 아닙니다.

감사 범위와 증거 수준

기준일은 2026-09-16입니다. 정식 제품의 당시 작업 트리에서 Frontend·Backend·API 계약·SQL·검색·보고서 코드를 조사했습니다. 문서, 화면, 타입 정의 또는 Mock만으로 구현 완료를 판정하지 않았습니다.

운영 DB 적용 상태, 실제 모델 가동, 언어쌍별 Retrieval 정확도·응답속도, 제조기업 SOP 권한의 실환경 효과는 이번 감사에서 미측정 또는 미검증입니다. 이전 성능 로그를 이번 다국어 개선 수치로 사용하지 않았습니다.

상태 의미: PARTIAL은 재사용 기반과 누락이 함께 있다는 뜻입니다. HARDCODED는 언어·문구·분기가 코드에 고정된 상태, UI_ONLY는 표시만 있는 상태, NOT_IMPLEMENTED는 조사 범위에서 기능 경로를 찾지 못한 상태입니다. READY는 요구한 종단 경로의 검증 완료를 뜻합니다.

실시간 데이터가 바뀌거나 다른 공장의 동명 Line을 가리키면 판정이 달라질 수 있습니다. “유사한 문장이면 언제나 같은 판정”이 아니라 동일한 정본 입력이면 동일 판정이 검수 기준입니다.

Locale·Chat·시간대 정책

P0는 ko-KR, en-US, vi-VN입니다. zh-CN, ja-JP는 P1 후보이며 검수 전에 선택지로 노출하지 않습니다.

로그인 후 UI 언어

명시 User 설정→권한 있는 Plant 기본값→Tenant 기본값→System ko-KR

설정이 없는 사용자 값은 상속 상태로 유지합니다. 모든 계정에 한국어를 강제로 저장하면 입력 언어를 따르는 정책이 막힙니다. 브라우저 언어는 미로그인 화면의 보조값으로 사용하고, 로그인 뒤에는 서버 권한과 저장 설정을 기준으로 결정합니다.

응답 언어 우선순위

  1. 현재 질문의 명시 지시: “영어로 답변” 등
  2. 명시적으로 유지한 대화/세션 언어
  3. 명시적으로 저장한 사용자 선호 언어
  4. 현재 질문에서 감지한 언어
  5. 짧거나 모호하면 이전 응답 언어
  6. 최종 UI 언어

인용 문서 속 “영어로 답하라”는 사용자 지시로 취급하지 않습니다. 실행 중인 요청은 시작 시의 언어 snapshot을 유지합니다.

Prompt: 언어별 정책 복제 대신 하나의 canonical prompt와 검증된 response_language를 사용합니다. 결론·근거·실무 조건의 구조 key는 유지하고 제목·본문만 Localize합니다. 정상 답변뿐 아니라 오류·메타 질문·연결 불가·진행 상태에도 같은 정책을 적용합니다.

날짜·숫자: Timestamp는 UTC, 날짜만 있는 시행일은 calendar date로 저장합니다. 표시는 Locale와 Time zone을 함께 지정합니다. Asia/Seoul과 Asia/Ho_Chi_Minh는 별도 설정이며 베트남어 선택만으로 시간대·통화·관할 규정을 바꾸지 않습니다. 베트남어 소수점 쉼표도 표시와 숫자 입력 파싱을 구분합니다.

Multilingual RAG 설계

현재 연결과 한계

코드에는 BGE-M3 1,024차원 dense → custom BM25 → 0.6:0.4 가중 RRF → LLM 재순위화 → 원문 인용 경로가 있습니다. BGE의 learned sparse·ColBERT를 모두 사용하는 구성은 아닙니다. 현재 비율을 다국어 최적값으로 검증하지 않았습니다.

OCR은 한국어·영어 중심이며 베트남어 스캔 SOP는 별도 검수가 필요합니다. 사내 문서 검색은 사용자 권한 연결이 완성되지 않아 차단된 상태입니다. 다국어 기능을 위해 이 보호를 우회하면 안 됩니다.

목표 시나리오코드 기반요구 workflow
A · vi 질문 → vi SOPPARTIALNOT_READY
B · vi 질문 → en 설비 매뉴얼PARTIALNOT_READY
C · ko 질문 → vi SOPPARTIALNOT_READY
D · en 질문 → ko 기술 문서PARTIAL공식 문서 PARTIAL / 사내 문서 NOT_READY

위 표는 live 검색 시험의 실패율이 아니라, 코드상 선행 조건과 평가 부재를 반영한 준비도입니다. BGE-M3의 다국어 지원 자체가 Haps의 한국어↔베트남어 제조 SOP 검색 성공을 증명하지는 않습니다.

C · 원문 + 번역 multi-query원문 경로를 유지하며 누락 보완중복·무관 후보·추적 복잡성번역·embedding·검색 증가

권고: A를 기준선으로 삼고, 측정된 부족이 있을 때만 C를 제한된 보완 검색으로 허용합니다. B는 비교 실험군입니다. 새 Provider 자동 우회나 특정 문서명·법정 정답 수치의 강제 매칭은 사용하지 않습니다.

Unicode 문자·성조·정규화를 보존하고 analyzer 버전을 기록합니다. 원문/번역 후보는 동일 원문 revision·chunk 기준으로 중복을 합칩니다. 언어는 검색 힌트이지, 권한이나 문서 범위를 대신하지 않습니다.

원문·번역 수명주기와 Evidence

Original Document = Canonical Source. Translation = Derived Artifact. 번역 생성이나 승인으로 원문을 덮어쓰거나 폐기 문서를 다시 활성화하지 않습니다.

AI_TRANSLATED→REVIEW_REQUIRED→HUMAN_VERIFIED→APPROVED_TRANSLATION

REJECTED·SUPERSEDED는 현재 판정 검색에서 제외합니다. 인간 검토만 끝난 상태도 최종 승인으로 간주하지 않습니다. 거절·폐기 후 수정은 새 artifact로 보존합니다.

검색 허용: 현재 사용자의 원문 권한, 원문의 승인·활성·시행 상태, hash 무결성을 먼저 확인합니다. 번역 후보는 여기에 최종 승인·원문 hash 일치·원문 segment 정합성이 추가로 필요합니다.

UI 제안: “원문 보기”를 기본으로 하고 “번역 보기”에 언어·승인 상태를 표시합니다. 미승인 번역은 허용된 경우에만 참고용 표시로 제공하며 판정 근거로 채택하지 않습니다. 원문 권한이 없으면 번역도 제공하지 않습니다.

원문이 개정·폐기되거나 권한이 회수되면 번역·인덱스·cache에도 반영해야 합니다. 번역의 페이지 번호를 원문 위치로 오인용하거나 새 원문을 과거 인용에 조용히 바꾸지 않습니다.

언어가 달라도 원문과 동일한 권한을 검색 후보 생성 이전에 적용해야 합니다. 후보 확장·재순위화·원문 보기·번역 cache 반환에도 같은 경계를 유지합니다.

번역 cache를 통한 실제 Tenant 유출을 이번 감사에서 발견했다는 뜻은 아닙니다. 미구현 기능을 추가할 때 방지해야 할 구조 위험입니다. 고객 문서 전송·새 번역 Provider·로컬 모델 설치는 이번 작업에서 실행하지 않았습니다.
